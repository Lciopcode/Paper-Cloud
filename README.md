# 论文云 · Paper Cloud

> **当前版本 `v0.3.0`**（2026-10-21）· 变更记录见 [CHANGELOG.md](CHANGELOG.md)
>
> 把 **arXiv 全部开放论文**（3,052,327 篇，1986–2026）的元数据，
> 按 **8 个学科 / 170 个研究方向**放进一座可漫游的三维星系。
>
> 而虚空里是「**一切可能的论文标题**」—— 编号 ⇄ 标题**双射**，算出而非存储。

**核心不变量**：位置由编号唯一决定。同一个编号，永远同一个位置。
所以它是一个**可以被验证的宇宙**，而不是一张好看的图。

## 快速开始

> ⚠️ **本机 `pnpm` 不在 PATH 上**（`where.exe pnpm` 找不到），所以下面一律写成
> **`corepack pnpm …`**（`corepack` 随 Node 一起装，实测可用，版本 `12.11.2`）。
> `corepack enable` 也能把 `pnpm` 装上，但它要写 `C:\Program Files\nodejs`，
> **需要管理员权限** —— 所以推荐前缀写法。
>
> 另外本机 **`git` 也不在 PATH 上**（在 `C:\Users\zlh318\.qwenworkcn\bin\git\cmd\git.exe`），
> 用全路径调用或把它的 `cmd\` 加进 PATH。

```bash
corepack pnpm install
node --max-old-space-size=8192 deploy/serve.mjs --port 5311   # 本地服务器（支持 HTTP Range）
# 浏览器打开 http://127.0.0.1:5311
```

> ⚠️ **为什么要 `--max-old-space-size=8192`**：点星取引用时会按学科建 100–150 万行的
> arXiv↔docId 表与标题索引（一个学科约 1–1.5 GB）。Node 默认 ~4 GB 堆在
> `physics` 索引 + 标题索引期间实测 OOM 直接退出（2026-10-21）。`corepack pnpm serve` 已带这个参数。

数据已经构建好并落盘（`public/data` 约 4.4 GB），**上述命令不需要网络**。

### 自带 API key（BYOK）—— 用你自己的配额取引用

HUD 右侧的「数据源」按钮可以粘贴**你自己的** Semantic Scholar / OpenAlex API key：

- key 只存在**这台浏览器的 localStorage**，只发给本机 `127.0.0.1` 的本地服务（`/api/*`），
  不上传、不入库；服务端不回显、不写日志，只回"这次用的是 `user` / `builtin` / `anonymous`"这一档；
- 面板列出每个数据源「内置 key 配没配 / 你的 key 填没填」，并可「测试连接」——
  服务端会用你的 key 发一次最小请求，回一行结论（HTTP 状态、耗时、一条真实样例）；
- 打开「实时引用」后，**没有本地引用表的学科**点星时也会向数据库实时取（首次需建该学科索引 10–30 秒）；
- 论文面板会标出「数据源：Semantic Scholar · 你的 key」—— 填的 key 有没有生效一眼可见。

> ⚠️ **数据源 ≠ 扩充星图语料**：星图仍然是本地 arXiv 的 3,052,327 篇。外部数据库只补
> 「这篇引用了谁 / 谁引用了它」的真实引用关系，不会把别的数据库的论文加进星图。

## 三个最该看的功能

### 1. 点一颗星，看它的关系网

点任意一颗星：镜头指数阻尼滑过去（τ≈0.17 s，不是切镜），在它身上炸出一圈冲击波，
留一个常驻的标记环，**同时把"关系丝线"里属于它的那些点亮、其余压暗** ——
于是这篇论文在文献网络里的位置一眼可见。

丝线是**算出来的关系**，不是装饰：11.4 万条「同技术路线」边，每一条的两端都是真实论文，
由标题+摘要的嵌入算出（`pipeline/build-edges.mjs` 离线构建，全量只有 3.9 MB）。
⚠️ 它们是**语义近邻，不是引用** —— 引用边需要外部 API，见 `docs/04-引用数据获取.md`。

### 2. 三种排列模式 —— 同一批论文，三种看法

| 模式 | 形态 |
|---|---|
| **领域** | 8 座独立旋涡星系 |
| **时间** | 一片盘，内圈 1986 → 外缘 2026；刻度环的**疏密**画出 arXiv 的指数增长 |
| **影响** | 引力井，越靠中心被引越多；**「无引用记录」单独落最外一环**（未知 ≠ 不重要） |

### 3. 层级下潜 —— 点研究方向只留那个方向

层号在构建期**写进了每篇论文的编号**，所以"只看某一层"是一次判断，
不需要重新索引。点层级面板里任一研究方向，29,272 个点里只剩 1,440 个亮着。

> **已删除**：原来的「虚空拉取」（随机取一个编号 → 算出标题 → 判定这个编号上有没有论文）
> 见 `docs/00-总结.md` 的说明。它守的那条不变量（编号 ⇄ 标题双射）没有丢，
> 改由 `src/engine/spine.assets.test.ts` 用**真实资产**验证。

`public/data/meta/*.{idx,txt,abs,venue}.bin` 与 `public/data/search/*.idx.bin`

## 诚实说明（写在最前面，而不是藏在附录）

1. **"全部论文"指的是 arXiv 的全部开放论文**，不是全世界的论文。
   arXiv 是 STEM 预印本库，人文社科覆盖很弱。
2. **引用数据目前覆盖率有限**（物理团 21.9%）。界面**如实显示覆盖率**，
   并且严格区分「**0 引用**」与「**没有记录**」——
   把后者画成"引用少"是把数据缺失伪装成结论。
   两个学术 API 的实际配额都低于官方文档（OpenAlex 实际 1000 次/天，
   是读响应头才发现的）。
3. **语义层（聚类 / 社区发现 / 路线命名）需要显卡**，本机（AMD 核显）未运行。
   交接包已就绪。
4. **引用边（backlinks）受 API 配额限制未抓取** —— S2 `/references` 不能批量，
   OpenAlex 需要先建 ID 映射表（约 30 天配额）。界面上不列这一项，
   而不是列一个点不动的筛选项。

## 目录结构

```
src/
  engine/      纯 BigInt 引擎（编号 ⇄ 词序列、Feistel 散射、前缀区间）零依赖
  data/        资产读取（Range 取字节）、契约、层级、检索、引用表
  three/       渲染（星点/星云/星桥/刻度环）、布局、着色器、几何
  state/       zustand store、永久链接
  ui/          HUD、面板、局部图
pipeline/      数据构建（导出 → 词表脊柱 → 元数据 → 检索 → 关系 → 引用）
pipeline_gpu/  语义层（需显卡；**已在 4090 上跑通**，八团陆续完成）
deploy/        本地服务器 + 17 项自检脚本（`node deploy/verify-all.mjs`）
docs/          文档
```

数据（4.4 GB）与 `text/`（1.3 GB）**不入库**，可由 `pipeline/` 重建。
仓库本身只有约 2.8 MB。
