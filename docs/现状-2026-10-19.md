## 3 引用功能（本次工作的重点）

### 3.1 结构

```
浏览器点星
  → GET /api/refs?domain=<学科>&doc=<docId>
  → deploy/serve.mjs 转给 deploy/api-refs.mjs
  → ① 先查 data/refs-cache/<学科>/<docId>.json（命中就 0 网络）
     ② 老式号（cs/9712101 这类）→ OpenAlex
        新式号（2401.00001）   → S2（带 key）；失败再退回 OpenAlex
     ③ 结果落盘缓存
  → 返回 { in: [库内 docId], ext: [[标题, 年, DOI]], source, arxivId }
```

### 3.2 已实测通过（证据）

| 请求 | 耗时 | 数据源 | 库外引用 |
|---|---|---|---|
| `cs/100`（arXiv `cs/9712101`） | 1.5s / 二次 107ms（缓存） | openalex | 14 |
| `math/500`（`math/9401216`） | 6.6s | openalex | 11 |
| `physics/3000`（`nucl-th/9301018`） | 19.2s | openalex | 20 |
| `bio/200` | 2.7s | openalex | 40 |

`cs/9712101` 的引用里能读到 `Optimization by Simulated Annealing (1983)`、
`Tabu Search—Part II (1990)` —— 内容是真的。

### 3.3 已知限制

1. **S2 今天 429**（响应体：`Too Many Requests … apply for a key`）。
   key 确认已读到（`.env.local`，长度 44，`deploy/probe-key.mjs` 可复验），
   请求头也确实带上了 —— 所以是**当日配额用尽**（抓可见星被引数花掉一百多次请求）。
   配额重置后新式号会走 S2；在此之前 S2 失败会自动落到 OpenAlex，不会“点了没反应”。
2. **S2 batch 不认老式 arXiv 号**：`ARXIV:cs/9712101` → `400 No valid paper ids given`。
   这是 OpenAlex 兜底存在的原因。
3. **「库内引用」目前普遍是 0**：命中的被引论文大多不在 305 万语料里（老论文）。
   要让线连到真实的星，需要额外做「反查谁引用了它」（OpenAlex `cites:` 过滤），还没做。
4. 个别请求慢（physics/3000 19 秒）：OpenAlex 要分两段查（作品 → 引用元数据）。
   已加落盘缓存，同一篇第二次 0.1 秒。
