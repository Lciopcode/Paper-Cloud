> 用一座可漫游的宇宙，装下 arXiv 全部开放论文，让"研究方向"看得见。

> ⚠️ **阅读须知（2026-10 更新）**
>
> 本文的**第 3.1–3.5 节记录的是 v1 的状态**（`研云/lunyun`），与 v2 有多处实质差异：
>
> | 本文写的（v1） | v2 的实际情况 |
> |---|---|
> | 目录每学科 40–51 位十进制 | **每学科统一 73 位**（V=4000 词 × S=20 槽） |
> | 地址表 `cell.bin` + 二分 | **编号表 `rank.bin`**（在编号空间判定，不在地址空间 —— 地址空间命中率约 10⁻¹²⁶，没有意义） |

> | 无元数据层 | **有**：标题/作者/年份/摘要/发表去处，用 HTTP Range 按需取字节 |
> | 无检索索引 | **有**：浏览器内 BM25，八团 126 MB / 1,980 万条倒排 |

## 一、这是什么

**论文云（Paper Cloud）** 把 arXiv 上公开可取的论文元数据（**3,052,327 篇**）组织成一座三维宇宙，
按 **八层学术层级** 嵌套展示，用户可以在其中漫游、下潜到任意一篇论文，
并沿 **三类关系边**（应用/被应用、同一领域、同一领域上的同一路线）在文献之间穿行。

**曾经的核心演示 —— 虚空拉取（2026-10 已删除）**：
点宇宙中的空白处，系统会 `unrank` 出一篇**从未存在过的论文标题**，并**确定地**告诉用户
"这个地址上真有一篇论文吗"。真实论文与虚构论文共享同一套坐标
（编号 ⇄ 标题双射，目录不被存储、被计算）。

**灵感来源**：刘慈欣《诗云》与博尔赫斯《巴别图书馆》。
形态上对应开源项目 [Cohenjikan/shiyun](https://github.com/Cohenjikan/shiyun)（诗云，PolyForm Noncommercial 1.0.0）。

## 二、一句话说明"和诗云有什么不同"

> 诗云是**诗人的宇宙**（诗人=恒星、诗=行星、赠诗=关系）；
> 论文云是**论文的宇宙**（论文才是主体，八层层级，引用=关系）。

| 维度 | 诗云 | 论文云 |
|---|---|---|
| 主体 | 诗人（3 万）+ 诗（33 万） | **论文（305 万，每一篇都是主体）** |
| 组织原则 | 朝代 + 诗人 | **学科门类 → 一级学科 → 大方向 → 子方向 → 课题 → 研究点 → 技术路线 → 论文** |
| 层级结构 | 扁平（诗人一层） | **八层嵌套** |
| 关系 | 赠诗（社交） | **引用 / 同领域 / 同路线（学术结构）** |
| 位置来源 | 编号哈希 | **层级 + 关系图布局（含语义计算）** |
| 影响力可视化 | 无 | **引用次数 → 星点亮度；发表评级 → 星点大小** |
| 无存储映射 | 有（核心） | **保留**（这是灵魂功能，但重写了双射构造） |

### 3.2 引擎（已完成，41 个单元测试通过）

纯 BigInt、零依赖的目录引擎：

- `rank` / `unrank`：编号 ⇄ 词序列（定长 base-V，首词为最高位 ⇒ 前缀锁定连续区间 ⇒ "半编号"）
- **双射散射**：对合 + 仿射构造 $\tau\circ m_n\circ\tau\circ\cdots\circ m_1$，把相邻编号在空间上打散且保持精确双射
  （**没有采用诗云的 cycle-walk Feistel** —— 实测它只在定义域是置换的并集时才是双射，此处做了算法取舍）
- `feistel` / `feistelInv`：8 轮，轮函数带 `+1` 消除全零不动点
- 地址表 `cell.bin` + 二分：确定判定"这个地址上真有论文吗"
- 永久链接：`#p=<学科>.<docId>`（真论文）、`#v=<学科>.<编号>`（虚构论文）、`#c=<学科>`（只看一团）

### 3.3 可视化（已完成第一版，正在重构）

- 四层渲染：星云尘埃（叠加混合）+ 真实论文星（正常混合+高斯软边）+ 远星天穹 + 核心柔光
- 每个星团是一座**真正的旋涡星系**：四条对数旋臂、扁平盘、暖核→蓝白臂的色温梯度
- 差速自旋、开场推入、`UnrealBloom` 后处理（过曝像素控制在 0.77%）
- 自由飞行相机（拖拽看向 / WASD / Space·C / Shift / 滚轮调速）
- 检索即星空过滤（未命中星点的 `aSize` 置 0，顶点着色器丢弃）
- 排版：**楷体衬线 + 鎏金渐变字**（`background-clip: text`）+ 宝石色学科配色

### 3.4 自检体系（已完成，这是参赛的"可验证性"证据）

### 3.5 审计结论

#### （a）v1 与诗云的关系（历史记录，**只对 v1 成立**）

| 判据 | 结果 |
|---|---|
| 源码文件 SHA256 完全相同的数量 | **0 / 165** |
| 有效代码行重合 | **294 / 6,408 = 4.59%** |
| v1 当时的结论 | 仿照重写（clean-room reimplementation），不是直接拉取 |

⚠️ **2026-10 订正**：上表那行"全部是通用样板"是**当时的自评，站不住**。
本轮的复核脚本（`_scratch/probe-code-overlap.mjs`）在 v2 上量到同类重合里
有相当一部分**不是通用写法** —— 比如 `galaxySpin.decorAngle = (galaxySpin.decorAngle + dt * DECOR_RATE) % (Math.PI * 2);`
这一行，**标识符名都与诗云一样**；双线性噪声插值、捏合调速钳制同理。
"文件哈希 0/165 相同"这个判据本身也没问题，但它**证明不了"不含其代码"**：
改名、重组、改语言（v1→v2 是 TS→TS+JSX）之后哈希必然全不同，重合的行照样重合。
**用哈希证明"没抄"，是用错了尺子。**

**v1 当时读了诗云哪些文件**（保留原记录）：`galaxyParams.ts`、`Galaxy.tsx`、`PoetStars.tsx`、`disc.ts` 完整读过（取星系配方常量），
`styles.css` 前 40 行（取鎏金配色），以及审计时读的 `docs/FRONTEND_GUIDE.md`、`docs/GESTURE_CONTROLS.md`。
当时**未读**其核心 `engine/engine.ts`、全部 `pipeline/`、全部 `gesture/`。
⚠️ v2 已不再受这个"未读"清单约束 —— 本轮为了照搬观感，`FlyControls.tsx`、`GiftLines.tsx`、
`disc.ts`、`touchGesture.ts`、`galaxyParams.ts` 都被完整读过并取用了常量。

#### （b）v2（本次交付）与诗云的关系（如实交代）

⚠️ **v2 与 v1 不同：v2 里明确移植了诗云的代码。**按作者指示，
本轮的目标就是"把诗云的观感逐项照搬"，移植是**有意为之**，不再假装清白。

## 五、已知的诚实边界（必须在作品说明里如实写明）

| 边界 | 说明 |
|---|---|
| **arXiv ≠ 所有已知论文** | arXiv 只有 STEM 预印本，无专著、无社科人文、无大量非英文文献。作品定位应说"arXiv 全量开放论文"，**不要宣称"所有论文"** |
| **引用覆盖率不完整** | Semantic Scholar 匿名接口限速（实测退避到 20 s/批），全量 305 万篇约需 35 天。策略：**高影响子集建完整引用边（20–30 万篇），其余按需拉取** |
| **发表评级是启发式** | 不引第三方期刊分区表（版权+体积），改用"是否正式发表 + venue 名称特征"分级，规则在代码里**可审计、可增补**，UI 上标明是启发式 |
| **"研究方向"是统计结果** | 语义聚类与社区发现的边界不是权威分类，需与 OpenAlex topic 交叉验证，UI 上不宣称是官方分类 |
| **作者名有歧义** | 未做作者消歧（同名不同人 / 同一人不同写法），作者检索结果需按此理解 |
| **版权** | 标题与摘要版权归原作者；只展示元数据，**不代理、不缓存、不分发论文原文 PDF**；非商业用途 |
