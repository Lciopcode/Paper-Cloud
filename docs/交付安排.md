## 1 项目是什么

**研云（Paper Cloud）**：把 arXiv **3,052,327 篇论文**按 **8 个学科**放进一座可漫游的三维星系。
每颗星 = 一篇论文；星的位置由语义关系决定，颜色 = 学科，大小 = 被引用次数；
点开一颗星，它亮起并牵出**真实的引用连线**（S2 / OpenAlex 双通道按需拉取）。

- 创作缘起：刘慈欣《诗云》——"把文明的全部作品铺成一座星云"；这里把它从诗搬到了论文。
- 参考实现：`D:\Develop\研云\研云\研云\v2\shiyun`（本地有源码，视觉与性能优化的对照物）。
- 参赛定位：数媒比赛国赛答辩用作品（PPT 另做，本仓库不含 PPT）。

### 3.2 第三轮新增：用户自带 key（BYOK）+「数据源」面板

**为什么做**：内置 S2 key 会被限流（429），OpenAlex 匿名只有 $0.10/天；用户若自带 key，
应该能用自己的配额与数据库权限。这就是"自带密钥"（bring your own key）。

**怎么用**：HUD 右侧「数据源」按钮 → 面板里粘贴 S2 / OpenAlex key（可加 OpenAlex mailto）→
点「测试连接」看服务端用**你的 key** 发的真实探测结果；打开「实时引用」后，
没有本地引用表的学科点星时也会从数据库实时取（首次需建该学科索引 10–30 秒）。
论文面板会标出「数据源：Semantic Scholar · 你的 key / 内置 key / 匿名」——key 有没有生效一眼可见。

**安全边界（已写进界面文案，也是实现约束）**
- key 只存**浏览器 localStorage**（`lunyun.s2Key` / `lunyun.openAlexKey` / `lunyun.openAlexMailto` / `lunyun.allowLiveRefs`）；
- 只发给同源 `/api/*`（本机 `127.0.0.1` 的 `deploy/serve.mjs`），不直连外部、不上传、不入库；
- 服务端只回凭据档位 `auth:{s2,openalex} = user|builtin|anonymous`，**绝不回显/落盘/记日志**；
- 默认 `type=password`，显示切换仅是本地状态。

**实测（`deploy/probe-source-keys.mjs`，10/10 PASS；无头 Edge + 真 GPU RTX 4090 D）**

| 项 | 读数 |
|---|---|
| 面板 | HUD 真实点击打开，`source-panel` 460×876；11/11 必需 testid 齐全；三条数据源如实显示「内置 key 已配置 / 未配置」 |
| 用户 key 优先生效 | 粘贴假 S2 key → 「失败 · **用你的 key** · HTTP 403 · 647ms」；同样请求不带头 → `builtin / ok / HTTP 200 / 328ms`（对照） |
| OpenAlex 匿名 | 「可用 · 用匿名 · HTTP 200 · 935ms · 被引 30」 |

## 4 已知问题（按优先级，全部有根因）

### ① 卡顿 —— **已解决（GPU 拾取）**
- 原主因：`StarPicker.pick()` 每次把全部星点用 CPU 投影一遍（305 万点时 215ms/次）；
  悬停被迫 250ms 节流还是卡。
- 现在：`src/three/gpuPick.ts` 用 GPU 颜色 ID 拾取 —— 只渲染**光标附近 29×29 像素窗口**
  到小 RT（`camera.setViewOffset`），读回 n² 像素解码。实测 305 万点 **1.8ms/次**（真 GPU），
  点数 ×10 耗时只 ×2.6。
- 细节：拾取点只画**中心 1 像素**（不是可见星盘大小），语义 = "光标 14px 内最近的投影中心"，
  与旧 CPU 版一致；门控与 `STAR_VERT` 相同（`uTopOnly`+`aTier`+`aSize`），所以**被 LOD 藏起来的星点不到**。
  中途试过"拾取盘=星盘大小"，在 305 万点密度下同一像素常叠 3–4 颗星，连点两次会给出不同 docId —— 已回退。
- 剩余：SwiftShader 下拾取仍慢（软件跑顶点着色器），但这只影响无头自检，不影响真机。

### ② 选中星"居中" —— **已验证成立**
见 §3.1②。链路 `StarPicker → selectPaper → FocusOnSelect → FlyCamera.focusTarget` 全部实测生效，
锁定距离 18、偏差 3.33px。若以后改相机/拾取，重跑 `deploy/probe-focus.mjs` 即可。

### ③ 部分论文"没有线"（数据边界，不是 bug）
线索要对**两端都在语料内**才能画。实测 `cs/434855`（2023）库内 0 / 库外 40——它引用的是 HCI/期刊文献，arXiv 语料里没有。
- 67% 的论文有库内引用 → 有线；剩下 33% 是边界。
- 本轮 OpenAlex 反查把"老论文只有库外引用"这一类补上了（见 #13）；想再提升只有扩语料（Crossref/机构数据），或接受边界。

### ④ S2 偶发 429 —— **已有双通道兜底（本轮补全反向）**
key 已接入（`.env.local`，长度 44，`node deploy/probe-key.mjs` 可验），请求头已带 `x-api-key`。
429 时自动退 OpenAlex（免费、配额独立）；本轮之前 OpenAlex 只取"它引用了谁"，
现在**两个方向都取**（`filter=cites:W…`），老式号/限流时也有反向线可画。
注意 OpenAlex 额度与历史缓存两条（§3.1③）。

### ⑤ 拾取歧义（设计内，不是 bug）
3M 点时屏幕平均约 2 点/px²，14px 半径内通常有几十颗星 —— "点 A 中心选中 1~2px 外的邻星"
是像素遮挡的结果。选中后 HUD 会显示编号/标题，用户能立刻看出选的是哪颗。
若将来要"更精确"，把 `PICK_RADIUS_PX`（`gpuPick.ts`）调小即可，代价是难点。

### ⑥ 服务端索引内存 —— **已解决（8GB 堆 + 串行队列）**
- 现象：`/api/refs` 首次查某学科要建 100–150 万行的 arXiv↔docId 双表 + 标题索引
  （一个学科约 1–1.5GB）。2026-10-21 实测：Node 默认 ~4GB 堆在 physics 索引 + 标题索引期间
  **OOM 直接退出**（`FATAL ERROR: Ineffective mark-compacts near heap limit`）。
- 现在：① 启动命令带 `--max-old-space-size=8192`（`package.json` 的 `serve` 已带；
  `serve.mjs` 启动时会打印堆上限警告）；② `loadIndex`/`loadTitleIndex` 加 **in-flight 去重**
  （同一学科并发请求共享一次扫描）；③ 大索引构建走**全局串行队列**（两个学科同时建会撑爆堆）。
- 若以后要同时打开 8 个学科的实时引用，建议把堆再抬到 12GB，并观察 `WorkingSet`。
- 相关：`serve.mjs` 里的堆上限提示、`docs/` 与本文件 §9 的启动命令。

### 5.1 调试桥新增（本轮，`window.__three`）
- `pickAt(clientX, clientY, radiusCss?)`：直接走 GPU 拾取，返回 `{domain, docId}` 或 null（与真实点击同源）。
- `pickStats()`：最近一次拾取耗时 `lastMs` / 命中 / 累计次数。
- `pickWindow(clientX, clientY, radiusCss?)`：返回窗口原始 id 网格 + `marks`（每个不同 id 的像素偏移与解码结果），排查"这个像素为什么不是那颗星"。
- `starVisible(domain, docId)`：`{tier, size, topOnly, visible}` —— 探针据此只挑**真正可见**的星做闭环。
- `visibleSample(domain, stride, max)`：按步长抽当前可见 docId（只扫一遍几何体，别用 `starVisible` 逐颗问）。
- ⚠️ **`selection` 不能 `JSON.stringify`**：`selection.record.rank` 是 BigInt（会抛 "Do not know how to serialize a BigInt"）。
  探针只读 `{kind, domain, docId, title}` 几个字段（`probe-pick.mjs` 里的 `readSelection` 就是范例）。
- ⚠️ `snap.mjs` / `verify.mjs` 用 SwiftShader 是**故意的**（像素口径可比）；拾取/帧率探针要真 GPU。

### 5.2 服务端接口（第三轮新增）
- `GET /api/sources`：数据源清单（`corpus` / `s2` / `openalex`），每项带 `builtin`（只报"内置 key 配没配"）、
  `keyHeader`/`keyParam`、说明与文档链接；`userKeysConfigured` / `auth` 只报布尔/档位。
- `GET /api/key-check?provider=s2|openalex`：用**这次请求头里的用户 key（没有就内置/匿名）**发一次最小查询
  （S2 查 ARXIV:0704.0062；OpenAlex 查同篇 work），回 `{status:"ok"|"rate_limited"|"error", using, usingUserKey, httpStatus, ms, note, sample}`。
- `/api/refs` 的请求头契约：`x-user-s2-key` / `x-user-openalex-key` / `x-user-openalex-mailto`；
  响应新增 `auth:{s2,openalex} = "user"|"builtin"|"anonymous"`。**所有接口都不回显、不落盘、不记日志 key。**
- 实现见 `deploy/api-refs.mjs` 文件头的「用户自带 key（BYOK）」一节；前端唯一出口是 `src/state/apiKeys.ts` 的 `apiKeyHeaders()`。

## 6 开发纪律（血泪，务必遵守）

1. **一次只改一处**，改完立刻：`tsc --noEmit` → `build` → `node deploy/snap.mjs` → 看非背景是否正常。
2. **改着色器按行号定位**，同一段 `gl_PointSize` 在多个着色器里都有；字符串替换曾把门控插进 11 个 `main()`，导致整屏黑。
3. **不要同时改混合方式 + 相机 + 亮度**（曾一次改三处，画面全黑）。
4. 关键提交前看 `git status`，`data/`、`.env.local`、`text/` 不提交。
5. 每个功能提交后，**用截图/接口数字**留证，不靠"看起来好了"。
6. **拾取相关改动**：必须跑 `node deploy/probe-pick.mjs --full`（真 GPU）+ `node deploy/probe-focus.mjs`；
   只看截图无法判断"点中的是不是那颗"。
7. **改 `deploy/api-refs.mjs` 后必须重启 5311**（模块在启动时 import），并用**未缓存**的 doc 验证；
   否则缓存会把旧结果返回给你，看起来像"改了没生效"。
8. 新增无头脚本一律用 `deploy/browser.mjs` 的 `resolveBrowser()/headlessArgs()/profileDir()`；
   `--user-data-dir` 必须绝对路径（相对路径会让浏览器静默忽略 CDP 端口，见 `browser.mjs` 注释）。
9. **启动服务必须带 `--max-old-space-size=8192`**（`corepack pnpm serve` 已带）。默认 4GB 堆在
   多学科实时引用建索引时会 OOM 直接退出（见 §4⑥）。
10. **改 `deploy/api-refs.mjs` / `serve.mjs` 后必须重启 5311**；加新接口先 `node --check` 再重启，
   然后在**同一进程**上用 `/api/sources`、`/api/key-check` 各打一次，确认不是旧模块。
11. **用户 key 相关改动**：跑 `node deploy/probe-source-keys.mjs`（约 2 分钟；`--skip-live` 跳过实时引用一条）；
    任何情况下不得把 key 写进响应/日志/缓存/证据 JSON（探针只用假 key，并断言假 key 不出现在响应文本里）。

## 13 数据源接入边界（2026-10-21 讨论记录）

用户问"有自己付费数据库 key 是不是也能用"。结论（与 `CHANGELOG.md` 末尾同一份记录）：

| 数据源类型 | 现在能否填 key 就用 | 说明 |
|---|---|---|
| Semantic Scholar / OpenAlex（含付费/免费 key） | ✅ 能 | 已有完整适配器，key 优先于内置 |
| 有公开 REST API + key 的库（Crossref、CORE、Dimensions 等，视条款） | ⚠️ 需加适配器 | 端点/认证/分页/字段解析 + 映射回 arXiv docId；不是"填 key 就行" |
| Web of Science / Scopus / IEEE / CNKI 等机构库 | ❌ 不能 | 多为机构 IP / OAuth / 专用客户端，无第三方按需公开 API；需机构网络或导出文件 |
| 任何库的导出文件（BibTeX / CSV / RIS） | ⚠️ 另一条路 | 可做「导入引用文件」：作为该篇的引用覆盖/缓存，不依赖 API |

三条不变前提：
1. **接上外部库也不会扩充星图语料**：星图固定为本地 arXiv 3,052,327 篇，外部数据只补引用连线与库外列表；
2. **许可**：`data/refs-cache/` 会落盘复用，付费库条款常禁止缓存/再分发，接前须确认；
3. **安全**：用户 key 只存浏览器 localStorage、只发给 `127.0.0.1` 本地服务，不回显/不落盘/不记日志。

**如果以后要加库**：接口已按"数据源清单"设计，新增一个 provider 只需
`deploy/api-refs.mjs`（端点/认证/解析）+ `SourcePanel` 一行 + 一份映射；
若只有机构登录/导出，则优先做「导入引用文件」，不要硬接 API。
