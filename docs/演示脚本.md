# 论文云 · 演示脚本（3 分钟）

> 每一句里的数字都是**实测值**，不是估计。验证方式写在括号里。
> 完整自检命令：`node deploy/verify.mjs`（另有 8 个专项自检，见 §五）。

---

## 零、开场前 30 秒（不做演示，只准备）

```bash
cd v2/lunyun
node deploy/serve.mjs --port 5311
```

浏览器开 `http://127.0.0.1:5311`，**按 F11 全屏**，鼠标移到画面中央。

预习一次"点星"（点一颗看效果），确认**丝线亮起来**了 —— 这是全场最容易被记住的一下。

**如果现场网络不通**：没关系，全部数据都在本地，`public/data` 有 4.4 GB。
只有 `pnpm install` 需要网。

## 一、开场（20 秒）——先给规模，再给"这个不一样"

> "这是 **arXiv 全部开放论文**的元数据 —— **305 万篇**，1986 到 2026 年，
> 分成 **8 个学科**、**170 个研究方向**。
> 每一颗星是一篇论文。"

（屏幕上此时是 8 座旋涡星系。数字来自 `verify.mjs` 的断言：3052327 / 8 / 170）

**拖一下鼠标让它转起来** —— 先让评委看到这是个真的三维场景。

> "但规模和三维都不是重点。重点是下面这件事。"

## 二、核心：点一颗星，看它的关系网（60 秒）——这是全场最该被记住的

**点画面里任意一颗星。**

镜头会**滑**过去（不是切镜），星星位置炸出一圈冲击波，然后留下一个常驻的标记环。
同时，铺满每座星系的**关系丝线**里，属于这篇论文的那些**亮起来**，其余压暗。

> "刚才这一下发生了四件事：镜头滑过去、炸一圈、留一个标记、**把这篇论文的关系点亮**。
> 最后一件才是重点 —— 这些线不是装饰，**每一条都是一条真实的关系**。"

**滚轮拉近一点**，能看到丝线怎么从一个中心射出去：

> "11 万 4 千条这样的线，铺在八个学科里。每一条的两端都是真实的论文，
> 由标题和摘要算出来的**同技术路线**关系 —— 两个人在做同一件事，就会有一条线。
>
> ⚠️ **必须说清楚：这是语义近邻，不是引用。** 引用边要向外部的 Semantic Scholar
> 逐篇取，我们正在申请 API key（`docs/04-引用数据获取.md` 里写了完整方案）。
> 现在画的是**手上真实有的**那部分关系 —— 这条边界我们宁可讲明白，也不混着说。"

**再点另一颗星**（换一个学科），对比一下：

> "换一篇，亮起来的线完全换了一批。所以这个网络不是画上去的，
> 是**从数据里长出来的** —— 你点哪儿，它长哪儿。"

**如果评委问「为什么不像别的作品那样先给一堆数字」**：

> "数字我们也有（右边面板：编号、年份、作者、发表去处，标题还是**由编号反算出来的**）。
> 但 305 万篇论文之间的关系，用表格是看不出来的 ——
> 所以我们把它变成了一座可以走进去的星空。"

（八层结构、编号 ⇄ 标题双射这些**仍然成立**，只是不再是一个按钮：
标题仍然由编号算出（面板里那串 73 位编号就是它），
这条不变量由 `src/engine/spine.assets.test.ts` 用真实资产守着。）

## 三、检索：让 305 万篇里相关的那批亮起来（40 秒）

**在搜索框输入 `galaxy`。**

> "305 万篇里，**20,832 篇**与 galaxy 相关 —— 它们**原样亮着**，
> 其余全部压暗到 7%。星系轮廓还在，所以你还知道自己站在哪儿。"

（右侧结果列表里是**真实标题 + 年份 + 期刊**）

```
Galaxy subgroups in galaxy clusters                    2012 · MNRAS
Galaxy-Galaxy Lensing as a Probe of Galaxy Dark Matter 2006
Galaxy And Mass Assembly: The xSAGA Galaxy Complement  2023 · MNRAS
```

> "检索在浏览器里完成 —— 倒排索引 **1,990 万条**、13.6 万个词，全部在本地。"

（数字来自 `manifest`：八个学科 postings 合计 19,903,530）

> "注意亮起来的不只是计算机团 —— 物理、生物、统计那边也有。
> 这不是我们安排的，是数据本身如此。"

## 四、三种排列（30 秒）——同一批论文，三种看法

**点「排列 → 时间」。**

> "八座星系重排成**一片盘**：内圈 1986，外缘 2026，每 10 年一圈刻度。"

**指着刻度环的疏密**：

> "看这些圈的**疏密** —— 1990 年代的圈几乎贴在一起，2020 年代的拉得很开。
> 这是 arXiv 的**指数增长**：物理团累计到 2016 年才刚过一半。
>
> 有趣的是，我们第一版按'年份等宽'排，画出来是个**甜甜圈** ——
> 论文全挤在外圈、中间一大片空白。查了数据才明白那不是 bug，是真实增长率。
> 后来改成按**论文量等分**，盘面就均匀了，而环的疏密反过来把增长率画了出来。"

**点「排列 → 影响」。**

> "第三种是**引力井**：越靠近中心被引越多。
> 高被引论文平均半径 2.61，低被引 4.27，0 引用 6.00。
>
> **而最外那一环是「还没有引用记录」的论文 —— 不是「没人引用」。**
> 它们单独分开放，因为把'数据缺失'画成'不重要'是最容易误导人的地方。"

## 五、下潜 + 遗迹 + 星桥（30 秒）——层级与跨学科

**点图例里「物理学」那一行的「演示」小标 → 打开层级面板 → 点任一研究方向**（例如「凝聚态物理·材料科学」）。

> "层号**写进了每一篇的编号里**，所以'只看这个方向'是一次判断，不需要重新索引。
> 29,272 个点里只留 1,440 个亮着。"

**关掉面板，点「遗迹」。**

> "这是**超新星遗迹**：我们逐年统计每个研究方向的产出，找出真正的**爆发点**。
> 最强的一次是 1997 年 —— **凝聚态物理的五个子领域同一年起爆**：
> 软物质 18.5 倍、强关联电子 18.0 倍、无序与神经网络 15.6 倍、统计力学 14.3 倍、超导 13.7 倍。
>
> 我们也标出了**假爆发** —— 比如电子工程 2018 年的 27 倍，
> 那是 arXiv 的 eess 分库那年刚建立、论文从别的分类迁过来，不是研究爆发。"

**点「星桥」。**

> "跨学科的弧线：强度是真的统计 ——
> 电子工程有 **80,572 篇**挂了计算机的分类，计算机到数学 **79,529 篇**（双向都大，真正融合），
> 而金融工程到经济只有 **565 篇**（强烈单向）。"

## 六、收尾（20 秒）

**点任意一颗星**，右侧出现完整论文面板。

> "标题、年份、作者、发表去处、被引次数、摘要、相关论文、局部图。"

**指左下角那行**：

> "这里写着：**'20.0% 的可见论文有引用记录 · 其余 80.0% 是数据还没抓到，不是引用很少'**。
>
> 引用数据是分批抓的，现在只抓了一部分。我们**不把它藏起来**，
> 也不把'没抓到'画成'引用少' —— 那是把数据缺失伪装成结论。
> 界面上每一处缺数据的地方，都写清了缺什么、为什么缺。"

**最后一句**：

> "这个作品要说的是：**位置不是画上去的，是算出来的**。
> 305 万篇论文、73 位的编号空间、8 个学科、170 个方向 ——
> 每一颗星的位置，都由它的编号唯一决定。同一个编号，永远同一个位置。
> 所以它是一个**可以被验证的宇宙**，而不是一张好看的图。"

## 七、如果被问到（准备好的答案）

| 问题 | 回答 |
|---|---|
| **"这是不是所有论文？"** | "是 **arXiv 全部开放论文**的元数据，305 万篇。arXiv 是 STEM 预印本库，不是全世界的论文 —— 这点我们在文档里写清楚了，不夸大。" |
| **"引用数据怎么只有 20%？"** | "两个学术 API 的配额都比官方文档写的低：OpenAlex 实际只有 1000 次/天（我们读了响应头才发现，文档说 10 万次）。S2 没有硬性日上限但共享池经常限流。我们选择**如实标注覆盖率**而不是假装完整。" |
| **"语义聚类呢？"** | "**已经跑了。** 用 `BAAI/bge-m3` 把标题+摘要编成 256 维向量（Matryoshka 截断 + int8 量化），再**在层内**聚类出第 5 层「具体研究点」、在近邻图上跑 Leiden 得到第 6 层「技术路线」。实测 4090 上 **145–176 篇/秒**（econ 12,486 篇 86 秒；数学团 575,978 篇 54 分钟），全量 305 万篇约 **5 小时**。 打开任意一篇论文，面板里能看到它属于哪个研究点、哪条技术路线。" |
| **"技术路线是怎么定的？"** | "两条证据交叉：语义近邻 **∩** 共被引。**但共被引那一路目前是缺席的** —— 引用边受 API 配额限制没抓到（见上一条），所以现在只有语义证据，脚本把它如实记进 `communities.json` 的 `degraded` 字段，界面上也标着'⚠️ 第 6 层是降级结果'。我们不把'相似'说成'同路线'。" |
| **"阈值的 0.65 是怎么来的？"** | "**量出来的。** 原来拍的是 0.80，结果最大的一条'技术路线'只有 8 篇、模块度 0.9912。我们写了 `analyze_route_threshold.py` 对一串候选阈值量了边数/连通分量/最大社区/单例社区/模块度，最后定 0.65：econ 最大路线涨到 **1,775** 篇、模块度落到 0.71。**判据不是模块度** —— 数学团 0.65 时模块度 0.927 反而更高，但它最大路线有 **56,560** 篇，显然不是碎片；真碎的是 0.80（最大只剩 969 篇）。这张表在 `community.py` 顶部，数字与产物一一对得上。" |
| **"性能怎么样？"** | "146 万点是一个 draw call。我们做了帧率监视：实测偏低时**自动降级**并告知用户，而且用户手动选过画质后就不再自动改。" |
| **"手机上能用吗？"** | "能。五种设备尺寸都有自检：抽屉默认收起（星空是主角）、触摸目标 ≥ 40px、输入框字号 ≥ 16px（否则 iOS 聚焦会放大整页）。" |
| **"AI 用了多少？"** | "全部代码由 AI 辅助生成，我们做了逐项验证 —— 见 `AI使用声明.md`。自检 **17 项**（`node deploy/verify-all.mjs`，约 496 秒）+ 单测 **220 项** + Python 侧两个契约自检（格式 13 项 / 续跑 10 项），每个 bug 的根因都写在提交信息里。" |

## 八、现场可能出问题的地方（附处理）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点了星"跳到另一篇" | 演示视图每 50 篇才画 1 点，会跳到**最接近的**那篇 | 面板里有距离提示，这是设计不是 bug |
| 第一次搜某个学科慢一两秒 | 检索索引按需加载（单团最大 62 MB） | 正常，加载后瞬时 |
| 「相关论文」第一次要等 | 邻接表按需加载（物理团 28 MB） | 正常 |
| 画面变暗了 | 触发了下潜/星尘流/遗迹筛选 | 对应面板里有"取消"按钮 |
| 自动变成低画质 | 实测帧率偏低，自动降级 | 点「画质」按钮可切回，切回后不再自动改 |

## 九、演示前 2 分钟自检（建议照做）

```bash
node deploy/verify.mjs           # 端到端 11 节
node deploy/verify-css.mjs       # 关键 CSS 规则真的在浏览器里（防"源码正常但规则被吞"）
node deploy/verify-mobile.mjs    # 5 种设备
```

三条都出 `✓ 全部通过` 就可以上台。
若某条失败，先看它打印的**具体数值**再判断 —— 这一轮修过的几个 bug
都是"源码看着正常、构建不报错、但结果错"，只有自检的数值能发现。
