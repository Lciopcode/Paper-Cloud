## 一、结论先说

**本项目在开发过程中使用了人工智能工具辅助，主要集中在"编码实现"与"数据处理脚本"环节；
作品的选题、概念设计、层级体系、取舍决策与验收标准由学生团队确定。**

人工智能工具在**作品运行时**的用途（即作品本身用到的 AI 能力）只有一处：
离线语义层使用开源文本嵌入模型对论文标题与摘要做向量化与聚类。
该模型**离线运行**，产出静态文件；**作品本身不含任何在线 AI 服务调用**，
**不上传任何用户数据**，**不向第三方发送任何请求**。

| 工具 | 版本/形态 | 使用环节 | 具体用途 | 人工干预 |
|---|---|---|---|---|
| **AI 编程助手**（对话式） | 会话式使用 | 编码实现 | 起草与重构 TypeScript 模块、编写单元测试、生成数据处理脚本、排查报错 | **团队逐行审阅、运行验证、按需改写**：所有代码均通过 `tsc --noEmit` 与单元测试后才能提交 |

| **开源文本嵌入模型** `BAAI/bge-m3` | 离线推理（GPU） | 作品的数据准备 | 把论文标题与摘要转成 256 维向量，供聚类与近邻检索 | 团队决定模型选型、截断维度、聚类分辨率；**聚类结果由人工抽检并校正标签** |
| 通用大语言模型 | — | **未使用** | ❌ 作品的运行时不调用任何在线大模型 | — |

### 关于"作品运行时是否使用 AI"

| 问题 | 回答 |
|---|---|
| 作品是否调用在线 AI 服务？ | **否**。纯静态，无后端，无 API 调用。 |
| 是否用 AI 生成展示内容（文案/图像/视频）？ | 论文元数据来自 arXiv，**不由 AI 生成**。演示视频若使用 AI 配音或字幕，将在 §五 单独列明。 |
| 是否用 AI 生成"虚构论文标题"？ | **不是 AI 生成的**。虚空标题由**确定性双射算法**从编号算出（词表 × 词槽的穷举空间），过程完全可复现、可用代码验证，与生成模型无关。 |
| 用户数据是否会被发送到第三方？ | **不会**。作品不收集任何用户数据，无账号、无埋点、无网络回传。 |

## 三、人工筛选与二次创作过程（官方重点核验项）

| 环节 | AI 参与程度 | 团队做了什么 |
|---|---|---|
| **选题与概念** | 无 | 团队确定"把论文组织成八层学术层级的宇宙"这一核心构想 |
| **学术↔宇宙层级映射** | 无 | 团队设计了完整的十二级映射表（学科门类↔宇宙网、技术路线↔恒星、奠基性论文↔近轨道行星……） |
| **评分标准适配与赛道候选** | 辅助调研 | 团队要求 AI 提取评分标准要点；**赛道不定型的决策由团队做出** |
| **编号引擎** | 辅助实现 | 团队确定"编号 ⇄ 标题双射、目录不被存储"这一机制；AI 起草 Feistel 与散射实现；**团队通过穷举测试发现并修正了两处双射缺陷**（逆轮序错误、cycle-walk 宽度重算） |
| **学科划分（8 个星团）** | 无 | 团队策展决定（arXiv 分类的归并方式） |
| **视觉语言** | **部分移植** | 星系观感（星团形态、星空着色器尺寸标定、HDR 辉光后期、相机操控与双指手势）**逐项移植自开源项目诗云**，其中 Bloom 参数 `1.4 / 0.1 / 0.28 / 0.85 / mipmapBlur` 与诗云 `App.tsx` 逐字相同；行级逐字重合 **337 行 = 我方 src 的 4.60%**（`_scratch/probe-code-overlap.mjs`）。**属于我们自己的**：八团学科配色、八层学术↔宇宙层级映射、关系丝线的语义（三类学术关系）、引用→亮度/评级→大小的编码。**移植的逐文件清单与 Required Notice 写在仓库根 `LICENSE` 的"第三方组件"一节。** |
| **数据来源选择与抓取策略** | 辅助实测 | AI 实测了各接口的可行性与限速；**"高影响子集优先 + 按需拉取"的取舍由团队确认** |
| **验收标准** | 无 | 团队确定（可运行、自检脚本零错误、性能指标） |

**关键点**：AI 起草的每一段代码都经过**可验证的测试**——
编号引擎有 **32 项**单元测试（含对全目录的穷举双射验证），
数据管线有产物自检；全项目单测共 **220 项**，另有浏览器自检 **17 项**
与 Python 侧两个契约自检（格式 13 项 / 续跑判定 10 项）。
**"AI 写了代码"不等于"AI 决定了作品"**：
所有取舍（做什么、不做什么、怎么算对）都由团队做出并被测试固定下来。

> 核对方式：`node node_modules/vitest/vitest.mjs run src/engine` → `32 passed`；
> 去掉参数跑全量 → `180 passed | 1 skipped`（那一项是可跳过的物理团规模预演）。
